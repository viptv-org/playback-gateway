# Extraction provenance

The engine was extracted from `viptv-org/backend`, commit
`5db5000eefa6833d5ed1ab47780cb8aba1919438`, directory
`server/playback-engine`. Original source and qualification tests are retained.
The GPL-2.0-only license and original attribution continue to apply.

Subsequent changes remove product-specific naming, separate the public service
contract and remove the arbitrary 1080p delivery clamp. This extraction does not
by itself change the deployed VIPTV backend or prove gateway cutover complete.

## In-process torrent/archive checkpoint

The torrent transport maintains canonical rqbit sources under
`third_party/rqbit`, patched through the root Cargo manifest. `Cargo.lock`
resolves librqbit 8.1.1, librqbit-core 5.0.0, librqbit-dht 5.3.1 and
librqbit-tracker-comms 3.0.0 to those local sources; the owning gateway commit
pins their complete contents. All four packages are Apache-2.0, with the
original Igor Katson copyright notice retained in
`third_party/rqbit/LICENSE` and the complete license in
`third_party/rqbit/LICENSE-APACHE-2.0.txt`.

librqbit and DHT originate from ikatson/rqbit commit
`00b97485160ff5b5aa2b379ea0815d568ec665f0`; core and tracker-comms originate
from `559fca8552f64099b39c9284c52fd4d3d9a9169f`. These deliberately distinct
revisions match the four previously locked registry packages. Source and
original manifest hashes, previous registry checksums and resolved upstream
symlinks are recorded in `third_party/rqbit/UPSTREAM.json`. Original canonical
manifests are retained under `third_party/rqbit/upstream-manifests`; working
manifests adapt sibling paths to this four-package layout. This adopts the
existing uncommitted source/ownership work and adds fenced joined completion,
queued IO ownership, cooperative cancellation and failed-settlement accounting.
See `third_party/rqbit/README.md` for interfaces and qualification limits.
No Cargo registry cache or generated normalized manifest is a maintained source.
The existing registry-resolved transitive package versions/checksums remain
unchanged in the root lockfile.

RAR reading pins `unrar-rs` 0.10.8 with its pure Rust crypto
backend. The latter's license is GPL-3.0-or-later with an additional unRAR
restriction; its full license, including the required restriction paragraph, is
preserved in [THIRD_PARTY/unrar-rs-LICENSE.txt](THIRD_PARTY/unrar-rs-LICENSE.txt).
It is a reader/extractor only. This repository provides no RAR writer or
compression implementation.

Inherited code and notices remain GPL-2.0-only. Archive-enabled in-process
binaries have an unresolved GPL-2.0-only/GPL-3.0-or-later distribution
incompatibility; these licenses are not claimed compatible. The engine's
`archive` feature owns unrar-rs and remains enabled in the default gateway build.
The selected-package native facade enables only `torrent`, excluding the archive
extractor and its dependency from its normal build graph. That exclusion does not
clear other dependency/license obligations or establish distribution readiness. The separate
process architecture remains an alternative if distribution is revisited.
UniFFI is pinned to the shared core's 0.29.4 binding generation pattern; its
generated Kotlin and native ABI compilation are gateway artifacts, not Android
client changes or release qualification.

Archive/media fixtures contain original locally generated byte patterns and
FFmpeg test patterns. Creation commands and provenance accompany
[byte fixtures](engine/assets/rar/README.md) and
[decodable fixtures](engine/assets/rar-media/README.md). The temporary RAR writer
is not redistributed. Cargo.lock pins dependencies; supply-chain/package
distribution review remains separate from local functional qualification.

## Native metadata validator attribution

The independent `torrent-policy/src/metainfo.rs` adapts VIPTV core's
`crates/viptv-core/src/native_metainfo.rs`. This generic added crate is GPL-2.0-only
and carries an explicit SPDX notice; it introduces no product identity. Its
network policy source is Apache-2.0. Inherited rqbit sources retain their
Apache-2.0 notices and package label; maintained librqbit-core consumes the
separate GPL-2.0-only policy crate. Native artifact inventory must report both
licenses and preserve notices. This does not clear unrelated distribution or
archive license findings.

The generic native network/metadata boundary and versioned bootstrap inventory
are documented in [native network policy](docs/NATIVE_NETWORK_POLICY.md).
