# Torrent/archive qualification

The transport is an opt-in local implementation, not a deployed backend/client
cutover. BitTorrent v1 uses scoped librqbit sessions and one global cache budget;
metainfo and direct stored archives retain the vetted HTTP egress seam. Runtime
support defaults off. HTTP trackers are stripped; private tracker torrents and
webseeds are refused. These are deliberate supported-subset limits, documented
because the pinned library lacks a vetted tracker client and webseed support.

## Byte transport and lifecycle

Deterministic host fixtures use a local BitTorrent TCP seeder, never the public
network. They verify largest-media/explicit selection, middle/suffix Range,
HEAD, 416 handling, token rejection, stable sharing within a namespace,
different namespace URLs, explicit stop, idle eviction and cache locking.
An HTTP tracker listener proves tracker metadata is not contacted. Metainfo
stripping preserves the exact raw info dictionary and original piece hashes.

Control fixtures verify runtime-off refusal before source activity, private
HTTP denial, direct stored-RAR ranges and source lifetime. Pending source
admission is registered before source I/O and promoted atomically into the
output ledger. Concurrent distinct inputs cannot spend the same key slot.
Canceled blocking extraction retains its global reservation and key admission
until actual completion; quota and byte-capacity regressions cover that case.
An output retains its input through actual worker/read teardown.

The cache reserves full logical torrent payload size before download, plus
declared compressed-member spool size before extraction. Active inputs cannot
be evicted; server reaping removes fully idle inputs promptly. Filesystem
metadata/block rounding remains outside the logical budget. Use the supplied
cache tmpfs or an equivalent independent filesystem limit for a kernel bound.

## Real media

Ignored host FFmpeg fixtures verify two viewers and a late viewer share one
HLS output, a separate VOD seek decodes a frame matching source time 3 seconds
rather than time zero, and final release reclaims input/output reservations.
Generated stored four-volume RAR media verifies shared HLS and seeking without
a spool copy. Compressed RAR verifies one complete checksum-verified spool,
byte identity with the generated source, shared output and seeking after
extraction. Fixture bytes and commands live in engine/assets/rar-media.

Run with real binary paths and one test thread:

```sh
CARGO_BUILD_JOBS=2 PLAYBACK_TEST_FFMPEG=/usr/bin/ffmpeg \
  PLAYBACK_TEST_FFPROBE=/usr/bin/ffprobe cargo test -p playback-gateway --lib \
  workers::torrent_tests::real_torrent_viewers_share_output_seek_and_reap_owned_input \
  -- --ignored --exact --test-threads=1
```

`scripts/check-torrent-container.sh IMAGE all` archives the committed source,
builds its Workers library fixtures, and executes them with the selected fresh
image's FFmpeg/ffprobe. Each test runs once as UID10001 with network none,
read-only root, no capabilities, two CPUs and bounded memory. The modes are
`torrent`, `stored-rar`, `compressed-rar`, `bounded-archive`, and `egress`. The bounded mode
uses an actual 2 MiB archive-cache tmpfs and checks preparation ENOSPC,
`processing_failed`, partial-spool removal and recovery. It does not qualify
failure of a previously ready viewer or the public service binary's API paths.
The egress mode verifies a selected playlist cannot reach a private HTTP child;
its generated byte root is authorized by exact URI while normal destination
validation protects nested requests. It also verifies nonstandard MP4 playlist
refusal on the qualified FFprobe version. Exact image/source evidence is
recorded in VALIDATION.md after execution.

All five modes pass with committed fixture source
`9217d34f1147250578bb6dc1b105de2e55316e75` and local runtime image
`sha256:3ed14fbbf179d9d4a326b6e798118ad62c209f01a7fdf3d0524233a52e367825`,
built from `da619d85a4d438b250db27415989a8b5a52e07ee`. The fixture follow-up
creates the compile-time asset path's missing parent and normalizes generated
Kotlin EOF; runtime Rust and dependency pins are identical. See VALIDATION.md
for per-mode results and the fixture repair. Hosts requiring sudo for Docker
must provide a PATH-visible wrapper so `timeout` can invoke it; exporting a
shell function alone does not cover that child executable.

The inherited progressive/runtime/CBR4K/bounded-media fixture builders include
the new ffi workspace member so they remain reproducible from Git archives.
The five required inherited progressive modes (`matroska`, `matroska-tls`,
`bounded-matroska`, `ts`, `bounded`) also pass with the same runtime image and
fixture source; their exact timings and separate live-media scope are in
VALIDATION.md. Runtime/CBR4K/bounded-media builders are mechanically updated,
rather than newly qualified by this torrent checkpoint.

## Native library

UniFFI host tests use the same local-seeder boundary and verify file selection,
byte seeking, progress callback and explicit stop. The four Android ABIs build
with verified ELF LOAD alignment of at least 16 KiB. This is compilation and
host-native evidence; APK ZIP alignment, Media3 consumption, devices and store
release are separate. The facade serves torrent payload bytes and currently
does not unpack archives. See ffi/README.md.

## Remaining acceptance

Public service-binary torrent/API qualification, local trusted-HTTPS browser
playback/seek, ready-viewer cache-exhaustion transport failure, sustained peer
workloads, unexpected process death and device integration remain unqualified.
The generic gateway's existing FFmpeg/media response failures retain their
separate qualification; those results do not substitute for torrent-specific
ready-viewer failure evidence. GPL distribution restrictions remain recorded
in PROVENANCE.md. No production data, deployment or migration is involved.

[Client integration and remaining qualification](https://github.com/viptv-org/playback-gateway/issues/15)
tracks the follow-up contract, actual service/API and trusted-HTTPS clients,
Android packaging/player behavior, ready-viewer failure and sustained/crash work.
It does not qualify those paths or authorize a production cutover.
