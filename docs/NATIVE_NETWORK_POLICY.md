# Native public network and metadata policy

Native sessions opt into `NetworkPolicy::PublicDhtTcpV1`, independently of legacy gateway torrent sessions. The generic session applies destination checks at the TCP connector, DHT request/routing lookup, returned peer, incoming datagram and final outgoing datagram boundaries. Bootstrap resolution rejects the entire answer set if any answer is denied. Native sessions have no peer-facing listener, proxy, blocklist fetch, tracker socket/worker, peer-exchange discovery/worker, UPnP mapping or persistence.

Bootstrap inventory `public_dht_tcp_v1-bootstrap-1` contains only `dht.transmissionbt.com:6881` and `dht.libtorrent.org:25401`. The inventory lives in `torrent_policy::network`, reexported by maintained `librqbit-core::network_policy`; input/grant fields cannot extend it. Artifact qualification records this inventory and source revision before advertisement. Local tests inject addresses/resolutions and contact no public peers or bootstrap hosts.

The conservative address policy denies the special-purpose IPv4 registry, multicast/reserved IPv4, and every IPv6 prefix outside global unicast `2000::/3`. Within that global range it also denies IETF special-purpose assignments, documentation, AS112 and transition ranges. All IPv4-mapped, compatible, NAT64, Teredo and 6to4 forms are refused, including forms embedding otherwise public IPv4. The registry inventory was checked against [IANA IPv4 special-purpose addresses](https://www.iana.org/assignments/iana-ipv4-special-registry/) and [IANA IPv6 special-purpose addresses](https://www.iana.org/assignments/iana-ipv6-special-registry/), each updated 2025-10-09. This conservative policy may refuse special-purpose globally reachable infrastructure; it does not make a routability guarantee.

`torrent_policy::metainfo` first scans raw bencode without allocating its value tree: at most 4 MiB, depth 32, 65536 values including dictionary keys, and 4096 file entries. Typed engine metadata and payload storage are created only after semantic validation. Canonical integers, ordered unique dictionary keys, v1-only keys, checked lengths and piece counts, positive payload lengths and safe paths are mandatory. NFC plus lowercase comparison rejects duplicate and overlapping path names; UTF-8 aliases must be NFC-equivalent without changing case. Separators, control characters, drive prefixes and trailing dots/spaces are refused. Errors and debug representations contain no input values.

Outer tracker fields are syntactically vetted without contact. Accepted annotations and trackers are removed by returning `d4:info<exact original info bytes>e`; the SHA-1 hash is computed over those unchanged bytes. Source nodes, peers, webseeds, alternate inputs, private/v2/hybrid/attribute/symlink and unknown fields are refused. Strict session admission requires non-serializable `NativeSelection` containing caller-verified canonical hash, explicit file index and positive verified selected size. Every identity check completes before payload file access. Discovery buffers refuse a zero or over-4-MiB advertised length before allocation and validate completed info before typed decoding.

`test-network-policy` is a non-default build feature for owned private TCP fixtures. It permits only the exact configured socket addresses and disables DHT. The production wire has no selector for it; qualified artifacts must omit that feature. Native settlement and full physical/public-peer qualification remain independent gates.
